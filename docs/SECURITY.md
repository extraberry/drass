# Security
bcrypt hashing (72-byte limit handled); generic login errors; lockout and idle expiry; session tokens stored only as SHA-256 hashes; server-side RBAC on every route; record-level visibility (`can_view_work`); uploads validated (size, extension, magic bytes, PDF opens), stored under UUID names outside any served path, atomic placement and cleanup on failure; SHA-256 recorded and re-verified at archive; no storage paths in API responses; append-only audit (no update/delete routes); CSV export neutralizes formula injection; raw tracebacks never returned. The reader is a **deterrent, not DRM** — screenshots/photos cannot be prevented. Known limits: no TLS by default (use a reverse proxy or campus VPN if needed), tokens are bearer tokens over HTTP on the LAN, no per-IP rate limiting.
