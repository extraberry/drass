# Implementation decisions
**Superseded by the manuscript (Chapter 3, latest revision):** the adviser review stage, the offline-approval reference, the administrator override, the Rejected status and the Head Librarian as a separate role are gone; see the first rows below and `WORKFLOWS.md`.
| Item | Decision |
|---|---|
| Manuscript is the source of truth | Roles: STUDENT, FACULTY, LIBRARY_STAFF, ADMIN, EXTERNAL_USER. Statuses: DRAFT, PENDING_VERIFICATION, RETURNED, ARCHIVED. Advisers, panelists and deans are Faculty and sign the approval sheet outside the system. |
| Head Librarian | A Library Staff account with `is_head_librarian` set by the Administrator (manuscript FR5: the Head Librarian performs the verification). Only the head verifies; other Library Staff see the queue read-only. If no active head exists the administrators are warned when something is submitted. |
| Rejection | The manuscript has only Returned and Archived, so there is no Reject. |
| Administrator | Cannot search, browse or read research (manuscript Table 13); keeps reports, indexing, backup and restore, users, settings, roster, integrations and logs. Reports are administrator-only. The earlier administrator override/archive feature was removed because the manuscript gives archival approval to the Head Librarian only. |
| Publication status | Set by the Head Librarian at approval, changeable by Library Staff. Public: all readers; Restricted: students, faculty, library staff; Unpublished: library staff and the owning student. External Users and guests see Public only. The integration catalog exposes Public only. |
| Companion files | Library Staff and the owning student can save them (`GET /repository/{id}/companions/{file}`); nobody else, including the administrator. The final PDF is never served as a file. |
| Category | Not in the manuscript's metadata list, so it is optional; the field is kept so existing data and filters still work. "Program" is displayed as "Course". |
| Backup | `backup_service`: database dump (mysqldump) + research files + manifest checksum; restore takes a safety backup first; admin page and scripts; scheduling through Windows Task Scheduler. |
| FR18 | No official school API is available, so the existing versioned `/api/v1` interface stays as the documented integration-ready option. |
| Optimistic lock | `research_works.version` + `expected_version` on verification calls; the work row is locked while it is verified. |
| Password / lockout / idle | Min 8 chars; 5 failures → 15-minute lock; 20-minute idle timeout; 12-hour absolute session. All editable by ADMIN (`system_settings`). |
| Auth error | Generic "Invalid username or password." Locked/deactivated messages are shown only for existing accounts. |
| Duplicate rule | Same normalized title + same author set + same year (excluding DRAFT records) blocks submission. No admin override in v1. |
| Upload limits | Research document (PDF) 100 MB; source-code archive 500 MB; video 500 MB; other supporting files 500 MB; each configurable by ADMIN (System Settings). The submission form shows the limit and accepted formats next to every upload button (read from `GET /public/upload-limits`), refuses a too-big file before sending it, and the server enforces it while streaming. Extension and magic bytes both checked; PDFs must open in PyMuPDF. |
| Search | **Hybrid**: the meaning score (best matching piece of the work) is combined with a word-match score (exact words, plurals, small typos, acronyms such as LMS; title/keywords count more than the abstract). A result is shown if its meaning score reaches the threshold (default **0.25**, was 0.35) or at least half of the query words match. Each work is embedded as several pieces (full text, title+keywords, 2-sentence abstract windows) because the model cuts long text at about 256 word pieces. Queries may be 2+ characters. Rebuild the index once after upgrading. |
| Recommendations | Cosine primary; small bounded metadata boost (program, department, category, keywords, year). On demand; not cached. Count configurable (default 5). |
| Archive failure policy | Files verified (exists + SHA-256) *before* the state change; failure leaves status unchanged, is audited and notifies admins. |
| Indexing failure | Work stays ARCHIVED; embedding FAILED with error; admins notified; retried every 10 min and via *Reindex Failed*. |
| Reader | Server renders one PNG per request (Cache-Control: no-store). No download/print/save. Deterrent only. |
| Schema creation | `create_all` for first install; Alembic configured, initial revision generated from models on a live MySQL (`--autogenerate`). |
| Search logging | Query text logged to activity_logs (truncated to 200 chars); switch off with setting `log_search_queries=false`. |
| Guest access | The app opens in guest mode: browse, filters, semantic search, record detail, related research **and reading** work without an account via `/public/*` (ARCHIVED records only, rate-limited per IP). Reading uses the same secure reader (page images, no download/print/save, every page view logged without a user). ADMIN can switch it off with the setting `guest_reading_enabled=false`. Guests still cannot see non-archived work, file lists or companion files. |
| Student self-registration | Only students on the registrar **roster** (`student_roster`, imported by ADMIN as CSV) can register. Required: student ID on the roster + matching last name; the account name comes from the roster, the role is always STUDENT. One account per student ID (`users.student_number` is unique). Failures use one generic message. Limitation: student IDs are not secret, so ID + surname is a weak check; stronger options (admin approval, school-email verification) are not implemented. |
| Integration design | Integration-ready, none bundled. Versioned `/api/v1/*` (stable) authenticated by hashed, scoped, revocable, expiring API keys (`roster:write`, `catalog:read`); keys are not accounts and cannot reach internal routes. Catalog export is metadata-only (no manuscripts, files, student numbers). Roster sync is an idempotent upsert. Webhooks, SSO and email are deferred. |
| Product name | **DRASS** (Digital Research Archiving System with Semantic Search) everywhere: window titles, header, login, messages, API title, `/health`, `APP_NAME` default. An interim build used the name "ResearchVault"; that was reverted so the demo matches the manuscript. Internal identifiers (`drass` DB, `drass_user`, folder names) never changed. New reference numbers use the prefix `DRASS-` (e.g. `DRASS-2026-00015`); references created by the interim build keep their `RV-` prefix. |
| Themes | Light and Dark mode (header button, also on the login window); choice stored per computer with Qt `QSettings`. |
| Demo password | Every demo account uses `Drass2026` (documented in `DEMO_ACCOUNTS.md`). Existing databases keep old hashes until `scripts\reset_demo_passwords.py` is run. Change before real deployment. |
| Username change | ADMIN can rename any user (Users → Edit). Letters, digits, `.`, `_`, `-`, 3–64 chars, must be unique (case-insensitive). The user's open sessions are revoked so they sign in again with the new name; audit action `USERNAME_CHANGED` records old → new. Records keep pointing at the user by id, so history is unaffected. |
