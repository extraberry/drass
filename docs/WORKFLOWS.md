# Workflows (Chapter 3 manuscript)
**Submission (FR4)**: Student saves a DRAFT (title, abstract, keywords, authors, year, course, department, adviser, dean) and uploads **one final PDF** (manuscript + completed approval sheet); optional companion files (source code, video). On *Submit* the system checks the required fields, that the adviser and dean are active Faculty accounts, that a PDF is attached, and that the research is not a duplicate (same normalized title + author set + year). Status becomes **PENDING_VERIFICATION**, revision 1 is stored and every active Head Librarian is notified (if none exists the administrators are told).
**Verification (FR5, FR6)**: only the **Head Librarian** (a Library Staff account designated by the Administrator) verifies. The checklist is: Adviser signed, Panelists signed, Dean signed, Researchers signed, approval sheet complete. 
- *Return*: any item missing, or any reason: remarks are required; status -> **RETURNED**; the student is notified and sees the remarks.
- *Approve*: every item must be ticked; the Head Librarian picks the publication status (Public / Restricted / Unpublished). Before the state change the stored PDF is checked against its SHA-256 checksum (NFR2); if it is missing or altered nothing changes, the failure is audited and the administrators are told.
There is no in-system adviser review, no panel or dean review, and no reject: signatures are obtained offline on the approval sheet.
**Resubmission**: the student fixes the metadata/PDF, enters change notes -> new `revisions` row (earlier ones kept) -> PENDING_VERIFICATION. Earlier verifications stay in the history.
**Archiving (FR7)**: on approval the record becomes **ARCHIVED**; `archived_at`, `archived_by` (the approving librarian) and `publication_status` are set, the verification (checklist, remarks, revision) is stored in `signatory_verifications`, then the title + abstract + keywords are embedded. An indexing failure never undoes the archive (status FAILED, administrators notified, retried every 10 minutes or by *Reindex Failed*).
**Publication status (FR10)**: Public - everyone who may read research (students, faculty, library staff, external users, guests). Restricted - students, faculty and library staff only. Unpublished - library staff and the owning student only. Library Staff can change it later; the change is audited. Search, repository, recommendations, the reader and the integration catalog all apply the same rule in SQL. The catalog exposes Public works only.
**Metadata (FR9)**: Library Staff edit archived metadata; each change is recorded old -> new in the audit log; if title, abstract or keywords changed the record is marked stale and re-indexed.
**Search (FR11-FR13)**: query -> local all-MiniLM-L6-v2 embedding of title, abstract and keywords only -> candidates the user may see -> cosine + word match -> threshold -> sorted. Filters: year, course, department, adviser, dean (and category/author/keyword). Recommendations are computed on demand from the same index.
**Reader and companion files (FR14, FR15)**: the final PDF is shown page by page as images in the secure reader (no download; each view logged). Companion files can be saved only by Library Staff and by the student who owns the work.
**Administrator (FR2, FR16, FR17)**: users, roles, Head Librarian designation, departments/courses, settings, roster, API keys, audit/activity logs, reports (administrator only, CSV export), indexing monitor, backup and restoration. The Administrator cannot search, browse or read research.
**Backup and restoration (NFR6)**: a backup set = database dump + copies of the research files + manifest with a checksum, written to `BACKUP_DIR` (separate storage). Restoring first takes a safety backup of the current state. See `BACKUP_AND_SYNC.md`.
**Reader**: client requests page N -> session + record access check (publication status) -> PyMuPDF renders a PNG -> returned with no-store headers; each view logged as PDF_PAGE_VIEWED.
